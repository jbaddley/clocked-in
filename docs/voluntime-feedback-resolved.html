This is your original letter, with answers written in. Your wording is unchanged. After each request is how it stands in the app today. The five questions at the bottom are answered. A short list of remaining decisions is at the end — please tell us which way you want those to go.

Jason, we really, really love VolunTime, and we're so excited about where it's headed. It already covers what we used Clockify for, and it does things Clockify never could for us: in-kind value built right in, group sessions, and the Needs board. Thank you for the care you've put into it.

The last two sections are a few bugs and cleanup items we spotted along the way, plus questions where I'd like your take before you build.

Roles and access

We need three levels of access, each able to log time for everyone below it.

Level Who Can do Closest role today
Super admin CASWJ staff Manage time for all groups and all volunteers. Run all reports. Submit time for group managers and volunteers. Admin
Group manager A leader in one or more member groups (Symphony, Youth Theatre, etc.) Manage and submit time for everyone in their group or groups. Log a whole group's effort, or the total volunteer effort for an event. Group coordinator
Volunteer Everyone else Track their own time and see their own history. Request access to more information when they need it. Volunteer
Done The three levels are in the product: Admin (CASWJ staff), Group manager (one or more groups), and Volunteer. Each can log time for the people they cover. We did not put “Super admin” on the volunteer-facing screens — that name is reserved for platform ops. In the app this level is Admin. “Group coordinator” is now Group manager. An extra Staff role still exists (reports, including a Staff tab). It is not one of your three levels — see the question at the end.

What's new compared with the current build:

  • Group managers covering several groups. Please confirm a coordinator can be assigned to more than one group and see combined reports.
    Done Yes. On People, invite, and access-request, an admin assigns Group manager per group. Someone who leads several groups logs time and runs reports for those groups together. They do not see groups they were not assigned.
  • Event-level totals. Group sessions today are tied to a group. We also need to log the total volunteer effort for one event, such as a show night with 40 helpers, without entering each person.
    Done Log Group Time records a session with a headcount. The group can be “whole organization,” so a show night of 40 helpers does not need 40 named people. Those hours stay off unique-volunteer counts.
  • Requesting access. A volunteer should be able to ask for more access from inside the app, and an admin approves or declines it.
    Done Volunteers request from their profile. Admins see it on People and approve or decline. Emails go out either way (and can be toggled on or off and customized under Settings → Email).
  • Custom roles. It would be great to have a permissions table where admins can adjust what each role can do and create new roles as we need them, instead of a fixed set.
    Done Settings → Roles. Admins can add a role and tick what it can do.

Inviting and importing people

Right now an invite only asks for an email and a role. We'd like the admin to set up the person's name and username when they send the invite.

  • Name fields. Add first name and last name to the invite form.
    Done The invite form asks for both.
  • Automatic username. Create the username from the first initial plus the last name, so Jane Smith becomes jsmith. If that's taken, tell the admin and add a number at the end (jsmith1, jsmith2). The invite email should then tell the person their username.
    Done Username is reserved when you invite (jsmith, then jsmith1). The form previews it before send. The invite email includes it.
  • Invitation subject line. Something like "CASWJ invited you to join VolunTime," with preview text such as "Log your volunteer hours with the Cultural Arts Society of West Jordan." The wording is open, so feel free to improve it.
    Done Subject is “{organization} invited you to join VolunTime.” Preview: “Log your volunteer hours with {organization}.” For CASWJ that reads as you described. Under Settings → Email, admins can also edit the subject, preview text, heading, and body for all 13 organization email templates.
  • Review before sending. When people are imported, show a list of names, usernames, email addresses and groups so the admin can confirm it before mass invitations go out. Please also make clear whether importing sends invitations automatically.
    Done Import shows a review list. Copy is explicit: import creates accounts and does not send invitations unless you check “Email users welcome credentials after import” (off by default). That optional email is a welcome with username and a temporary password, not the CASWJ invite. Existing emails are skipped, or merged if the admin picks merge.
  • Duplicate check on import. The Import screen says existing records are skipped, but it doesn't say how a match is found. In that review list, flag rows that match existing people or projects, including near-matches like the same name with a different email, so the admin can skip, merge or import each one.
    Done Same email, or same name with a different email, is flagged. Each row can be skipped, merged, or imported.
  • CSV templates. Add a "Download template" link for the People and Project / Events imports so we know which columns to use.
    Done “Download template” is on People and on Projects / Events. People headers include Email, First name, and Last name (required), plus optional username, role, group, and the rest of the import fields.
  • Drop the Groups import. We'll rarely add groups, so it isn't needed. Adding them one at a time on the Groups screen is fine.
    Done Import is People and Projects only. Add groups one at a time on the Groups screen. (A script endpoint still exists for developers; volunteers never see it.)

Projects and events

  • Archive old projects. An archived project or event stays in reports and past entries but no longer appears in dropdowns. The hourly rates screen already works this way, so the same pattern would fit.
    Done Archive / unarchive is on Settings → Projects. Archived projects stay in history and reports and drop out of placement dropdowns.
  • Add a project from any dropdown. Wherever someone picks a project or event (logging time, group sessions, Needs), add a "+ New project / event" option so they don't have to go to Settings first. It could be limited to admins and group managers.

Needs

  • A public Needs page. Anyone can browse the open public needs without logging in, then send a sign-up request from there.
    Done The public catalog is at /openings/{organization-slug}. Anyone can browse published public needs and open a sign-up from there. Logged-in /needs stays the management screen, so staff do not share an admin URL on wjarts.org. Each need still has its own sign-up link.
  • What's there now. The Add need form already has "Allow a public sign-up link." A link for each need is a good start, but a single page listing all public needs is what we'd share on wjarts.org and social media.
    Done That listing page is the openings URL above. Share that one link on wjarts.org and social. See the question at the end if you would rather have a shorter public path.
  • Group managers can post needs. A group manager can create a need for their own group. It goes to an admin for approval before it's published, and the manager hears back either way.
    Done Group managers can create a need. Without approval permission it stays pending until an admin Publishes or Rejects. The manager gets an email either way (configurable under Settings → Email). Logged-in Needs now has a Status column, a Pending review filter, and Publish / Reject on the list. Admins see every need in the organization. Group managers see needs they posted and needs for groups they lead.
  • Vetting. The "Require vetting" option and the custom questions already fit this flow well.
    Done Unchanged. They still sit on the need and on public sign-up.

Classifying time and the dashboard

Grant reports are only as good as how people classify their hours, so a few prompts would help a lot.

  • After stopping the timer. Show a short reminder to check the project, task category and group before saving.
    Done After Stop: “Check this time before saving.” Project, category, and group are still editable. You can leave them blank and classify later.
  • Unclassified entries. An entry with no project, no task category and no group counts as unclassified. Notify people about these entries, asking them to classify the time or delete the entry.
    Partial Blank project, category, and group = unclassified. There is an in-app banner that links to those entries, and an email after a timer clock-out (classified saves can also send a “Logged time” confirmation email). Under Settings → Email, admins control when emails are sent — setting both Logged time and Unclassified entry to Immediately, Weekly digest, or Off, and toggling any other optional notification email on or off. Handwritten duration / total hours can also save with blank placement today; they show in the banner, but they do not send that email (email is clock-out only). We recommend keeping classify-after for the timer, and not letting typed grant hours sit blank if we can help it — see the question at the end.
  • Tags. Admins keep managing the tag list so we can add more detailed tracking later. If there are no tags, hide the Tags field from users.
    Done Volunteers do not see Tags until you add some. Admins still see the field so they can create the first one.
  • Clickable dashboard cards. Each card should open the detail behind it. For example, clicking "Your hours" opens your entries, and clicking a category in "Hours by task category" opens the entries in that category.
    Done Cards, chart slices, and list rows open filtered Entries — person, category, project, group, unclassified, and date range are passed through. Example: Hours by task category → Dancing opens only Dancing entries. Admins can switch the person filter to Everyone.

Open questions

  • ☑ Does importing people send invitations automatically?
    Answer No. Import creates the person’s account right away. It does not send an invite unless the admin checks Email users welcome credentials after import (off by default). That email is a welcome with username and a temporary password, not the “CASWJ invited you to join VolunTime” invite. If you want someone to accept an invite and pick their own password, use Invite, not Import.
  • ☑ Can a group coordinator manage more than one group today?
    Answer Yes. An admin can assign someone to several groups and mark Group manager on each one they lead. That person can log time and run reports for those groups together.
  • ☑ Project and task category are required today, so unclassified entries can't happen yet. Should the timer save without them so people can classify their time afterward?
    Answer Yes for the timer. You can start and stop without a project, category, or group. After Stop, the reminder asks you to check those fields and says you can leave them blank and classify later. Blank on all three is unclassified: banner in the app, email after clock-out (configurable under Settings → Email as Immediately, Weekly digest, or Off). For handwritten duration and total hours we still recommend picking a project and category before save — see the remaining question below.
  • ☑ What should we call the levels? In the app, "organization" means CASWJ and "group" means the Symphony, Youth Theatre and so on. Let's match the labels to how volunteers talk.
    Answer Match how volunteers talk. CASWJ seed already uses these labels:
    • Organization — CASWJ
    • Group — Symphony, Youth Theatre, and the other affiliates (not “department”)
    • Project / Event and Task Category — unchanged
    Access levels in the product:
    • Admin — CASWJ staff. Your “Super admin.” We do not call this Super admin in the app.
    • Group manager — a leader of one or more groups
    • Volunteer — own time and own history; they can request more access
    Optional extra: Staff (can see reports). Not in your three levels. See the question below.
  • ☑ Is sign-up from a public Need the same as self-signup, or does it create a request an admin approves?
    Answer It is not the same as creating a login. Signing up for a public Need records interest (name, email, optional vetting). A guest can do that without an account. A signed-in volunteer signs up as themselves. The form has a separate checkbox: Also request an account so I can log hours in VolunTime. That sends an access request an Admin approves. Until then, the person is a guest on that Need only. Open Create account is a different path, and the CASWJ portal can turn it off so people join by invite or by that Need request.
